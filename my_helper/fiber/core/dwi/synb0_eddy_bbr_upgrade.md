# DWI preprocessing with Synb0-DISCO, eddy, and Lead-DBS pseudo B0 coregistration

This document describes a project-agnostic diffusion MRI preprocessing workflow
used to generate a distortion-corrected diffusion series and a corrected mean b0
image that can be reviewed through the standard Lead-DBS coregistration
interface. The workflow is designed to reuse Lead-DBS functionality with minimal
changes to the normalization code path.

## Overview

Diffusion-weighted images are first staged in a BIDS-compatible layout and
validated against their JSON, bval, and bvec sidecars. A distorted mean b0 image
is extracted from the staged diffusion series and passed to Synb0-DISCO together
with the subject-specific anchorNative T1w image. The synthetic undistorted b0
generated by Synb0-DISCO is used with FSL topup and eddy to correct
susceptibility, eddy-current, and motion-related distortions. A corrected
diffusion series, rotated bvecs, and a corrected mean b0 image are then written
to the Lead-DBS preprocessing directory.

The corrected mean b0 is exposed as the existing Lead-DBS pseudo `B0` modality.
This makes the image visible to the `Coregister Volumes` UI without adding a new
UI entry point. The pseudo `B0` is used only for coregistration review and
quality control. It is explicitly removed from the normalization input structure
inside `ea_normalize` before any normalization backend is called.

## DWI import and validation

The import stage copies BIDS-compatible DWI files into the study `rawdata`
directory. Other projects can provide the same layout directly without using the
STNSNr import script. For each included subject, the expected input set is:

```text
rawdata/sub-<ID>/ses-preop/dwi/sub-<ID>_ses-preop_dwi.nii.gz
rawdata/sub-<ID>/ses-preop/dwi/sub-<ID>_ses-preop_dwi.json
rawdata/sub-<ID>/ses-preop/dwi/sub-<ID>_ses-preop_dwi.bval
rawdata/sub-<ID>/ses-preop/dwi/sub-<ID>_ses-preop_dwi.bvec
```

Before distortion correction, the batch runner checks that the DWI image and
sidecars are present, that the NIfTI image is readable, and that the bval and
bvec counts match the number of DWI volumes. Subjects are provided explicitly,
read from an import log, or discovered from `StudyRoot/rawdata/sub-*`. The staged
DWI is copied into the Lead-DBS derivative tree before preprocessing so that the
raw provenance copy in `rawdata` remains unchanged.

## Susceptibility distortion correction

When `DistortionCorrection` is set to `synb0`, the workflow performs the
following correction steps.

1. A distorted mean b0 is extracted from all volumes with `bval < 10`.
2. Synb0-DISCO is run with the distorted b0, anchorNative T1w image, and
   `synb0_acqparams.txt`.
3. The Synb0-DISCO topup output is passed to eddy.
4. Eddy writes the corrected DWI series and rotated bvecs.
5. The corrected DWI is copied into the formal Lead-DBS preprocessing location.

The phase-encoding vector defaults to `[0 1 0]`. `TotalReadoutTime` is taken
from the raw DWI JSON when available; otherwise the documented default value
`0.05` is used and recorded in the status and QC outputs. Single-shell DWI runs
use eddy with `--data_is_shelled`.

Synb0-DISCO is executed through Docker or Singularity. The default image is
`leonyichencai/synb0-disco:v3.1`. A FreeSurfer license is required and can be
provided explicitly or discovered from standard locations, including:

```text
/Applications/freesurfer/8.2.0/license.txt
```

The Docker preflight checks the Docker Desktop memory limit. The default minimum
is 12 GB because Synb0-DISCO inference can fail when the container is given too
little memory.

## Corrected B0 generation

After eddy completes, the corrected mean b0 is extracted from the corrected DWI
using the same `bval < 10` criterion. The formal outputs are:

```text
derivatives/leaddbs/sub-<ID>/preprocessing/dwi/sub-<ID>_ses-preop_desc-preproc_dwi.nii
derivatives/leaddbs/sub-<ID>/preprocessing/dwi/sub-<ID>_ses-preop_desc-preproc_dwi.bval
derivatives/leaddbs/sub-<ID>/preprocessing/dwi/sub-<ID>_ses-preop_desc-preproc_dwi.bvec
derivatives/leaddbs/sub-<ID>/preprocessing/dwi/sub-<ID>_ses-preop_desc-preproc_b0.nii
```

The corrected b0 sidecar records its pseudo-modality role:

```json
{
  "FakeCoregisterVolume": true,
  "IntendedUse": "coregistration_qc_only",
  "ExcludeFromNormalization": true
}
```

The JSON sidecar also stores the corrected DWI path, rotated bvec path,
phase-encoding vector, readout-time source, topup field output, and the expected
Lead-DBS UI coregistration target.

## Pseudo B0 exposure to Lead-DBS

`BIDSFetcher.getPreprocB0()` searches the subject's `preprocessing/dwi`
directory and preferentially returns `*_desc-preproc_b0.nii`. Lead-DBS then
exposes this image through `options.subj.preproc.anat.preop.B0`, which allows the
standard coregistration UI to treat the corrected b0 as a pseudo preoperative
volume.

The expected UI output target is:

```text
derivatives/leaddbs/sub-<ID>/coregistration/anat/sub-<ID>_ses-preop_space-anchorNative_desc-preproc_B0.nii
```

The batch status is set to `pending_ui_coregistration` and the coregistration
status is set to `pending_ui`. This records that the corrected b0 has been
prepared but the UI-based anatomical alignment and manual QC have not yet been
accepted.

## Coregistration and manual quality control

After the corrected b0 has been generated, the subject should be opened in the
Lead-DBS UI and processed through `Coregister Volumes`. The pseudo `B0` should
usually be aligned with SPM first, because it is the preferred initial method for
this workflow and is readily available through the Lead-DBS UI.

The output must be reviewed manually before it is accepted. The reviewer should
inspect whether the corrected b0 agrees with the anchorNative anatomy at the
brain outline, ventricles, basal ganglia, midbrain, and brainstem. If SPM gives
poor anatomical agreement, the coregistration should be rerun with another
Lead-DBS-supported method, such as ANTs. The method with the best anatomical
agreement on visual QC should be retained for downstream use.

The pseudo `B0` is not an anatomical contrast for normalization. It is a
distortion-corrected diffusion reference volume used to support DWI-to-anatomy
QC.

## Normalization safety

The standard normalization entry point is `ea_normalize(options)`. Before calling
`ea_norm_refine_prepare()` or any normalization backend, the function removes
`B0` from its local copies of:

```text
options.subj.coreg.anat.preop
options.subj.norm.anat.preop
```

This upstream filtering keeps the pseudo `B0` visible to the coregistration UI
while preventing it from entering ANTs, SPM Segment, SPM Shoot, SPM Dartel,
Schonecker, or other normalization backends reached through the standard
Lead-DBS normalization path.

## Outputs and provenance

Each Synb0 fake-B0 run writes a status CSV under:

```text
derivatives/leaddbs/import_logs/
```

The status and subject-level QC JSON record the distortion-correction method,
phase-encoding vector, readout-time value and source, corrected DWI path,
corrected b0 path, fake-B0 sidecar path, topup field path, rotated bvec path,
and UI coregistration status.

QC overlays are written under the subject-specific QC directory. The automatic
overlay compares the distorted b0 with the corrected b0. The corrected b0 to
anatomy overlay is reviewed after the Lead-DBS UI coregistration step.

## Quality control criteria

The corrected b0 should be accepted only when the following checks are satisfied:

- the corrected b0 has plausible brain geometry and no obvious polarity failure;
- the corrected b0 improves or at least does not degrade the distorted-b0 shape;
- the DWI volume count matches the bval and bvec counts;
- the rotated bvec file has one direction column per corrected DWI volume;
- the UI coregistration result aligns the b0 with the anchorNative anatomy;
- the selected UI method is documented in the subject status or project notes;
- no `B0` image is produced in the normalization output directory.

If these criteria fail, the phase-encoding vector, readout time, Synb0 output,
eddy output, and UI coregistration method should be reviewed before the subject
is used for tractography or downstream group analysis.
